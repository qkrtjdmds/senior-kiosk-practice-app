# 한걸음 디지털 V3 기능 범위 및 로드맵

## 1. 문서 목적

이 문서는 `v2.0.0`의 기능과 로컬 데이터를 보존하면서 V3의 범위를 결정하기 위한 설계 문서다. V3 설계 단계에서는 로그인, 서버, 실제 결제, 구독, 광고 SDK를 연결하지 않는다. 기존 7개 연습은 계속 무료로 제공한다.

## 2. V2 기준선

- Flutter 3.41.5, Dart 3.11.3, Material 3
- `provider`, `go_router`, `shared_preferences` 기반
- 카페, 햄버거, 병원, 기차표, ATM, 무인민원발급기, 사진 보내기 V2
- 자유 연습, 따라 해보기, 혼자 해보기, 한국 날짜 기준 오늘의 미션
- 연습 포인트, 완료 횟수, 배지, 최근 기록
- 온보딩, 글자 크기, 선명한 화면, 기록 초기화
- 코드 기반 한걸음이 캐릭터, Android 아이콘과 네이티브 Splash
- 로그인, 서버, 네트워크 API, 실제 결제, 실제 개인정보 권한 없음

V3에서도 V2의 공개 동작과 SharedPreferences 키를 그대로 유지한다.

## 3. V3 목표

1. 어르신이 혼자서도 안내를 다시 듣고 연습할 수 있게 한다.
2. 업데이트 뒤에도 V2 기록을 잃지 않는다.
3. 무료 사용자는 기존 7개 연습과 기본 미션을 계속 사용한다.
4. 공지와 도움말을 개인정보 수집 없이 제공한다.
5. 신규 가상 연습을 작은 단위로 추가한다.
6. 향후 계정, 운영 도구, 구독을 붙일 수 있는 경계를 만들되 지금은 운영 비용을 늘리지 않는다.

## 4. 기능 후보 분석

### 4.1 계정

| 후보 | 가치 | 난이도 | 주요 고려 사항 | 권장 |
|---|---|---:|---|---|
| 로그인 없이 계속 사용 | 매우 높음 | 작음 | 현재 접근성과 개인정보 최소화 원칙 유지 | V3 필수 |
| 이메일 로그인 | 중간 | 큼 | 이메일 검증, 비밀번호 찾기, 탈퇴, 지원 업무 필요 | V4 이후 |
| 소셜 로그인 | 중간 | 큼 | 제공자별 정책, 계정 병합, 탈퇴 연동 필요 | V4 이후 |
| 기기 기록을 계정에 연결 | 높음 | 매우 큼 | 중복 병합과 동의 UI가 핵심 | V4 이후 |
| 기기 변경 시 복원 | 높음 | 매우 큼 | 인증과 서버 동기화가 선행되어야 함 | V4 이후 |
| 로그아웃·탈퇴·비밀번호 찾기 | 필수 부속 | 큼 | 계정 도입 시 함께 제공해야 함 | 계정과 동시 |

계정을 도입하더라도 게스트 사용을 기본 경로로 유지한다. 로그인 때문에 첫 화면이나 연습 시작이 막혀서는 안 된다.

### 4.2 기록 동기화

- 포인트와 완료 횟수는 단순 합산하면 같은 완료가 중복될 수 있으므로 이벤트 ID 기반 멱등 병합이 필요하다.
- 배지는 획득 여부의 합집합으로 병합할 수 있다.
- 최근 기록은 고유 ID로 중복을 제거하고 최대 보관 개수를 적용한다.
- 오늘의 미션은 한국 날짜와 미션 ID를 함께 저장하고 완료 이벤트만 병합한다.
- 글자 크기와 대비는 기기 특성이므로 기본적으로 기기별 설정으로 둔다.
- 오프라인 변경은 로컬 큐에 저장하고 연결 시 재시도한다.
- 충돌 시 서버 시각만 믿기보다 이벤트 ID, 생성 기기, 스키마 버전으로 판정한다.

이 범위는 서버와 계정이 필요한 큰 작업이므로 V3 기본안에서는 제외한다.

### 4.3 구독

#### 무료 유지 범위

- V2의 7개 콘텐츠
- 자유 연습, 따라 해보기, 혼자 해보기
- 기본 오늘의 미션
- 기존 포인트, 배지, 최근 기록
- 기본 접근성 설정

#### 구독 후보 범위

- V3 이후 추가되는 일부 신규 콘텐츠
- 추가 미션 묶음
- 상세 성장 리포트

기본 Android 기기 내 TTS, 다시 듣기와 속도 설정은 무료 도움 기능으로 유지한다. 무료 기능을 사후에 유료로 전환하지 않는다. 결제를 재촉하는 전면 팝업이나 혼동되는 무료 체험 표현도 사용하지 않는다.

Android 앱 안의 디지털 콘텐츠 구독은 원칙적으로 Google Play Billing 정책 검토가 먼저다. 한국에서는 허용 프로그램에 가입하고 관련 API와 거래 보고 요건을 충족하는 경우 대체 결제를 함께 제공할 수 있으나, 외부 결제 링크를 임의로 넣을 수 있다고 가정해서는 안 된다. 정책은 바뀔 수 있으므로 구현 직전에 [Google Play 결제 정책](https://support.google.com/googleplay/android-developer/answer/10281818?hl=ko), [Play Billing 문서](https://developer.android.com/google/play/billing), [한국의 대체 결제 안내](https://support.google.com/googleplay/android-developer/answer/13821247?hl=ko)를 다시 확인한다.

스텝페이는 웹 결제 페이지, 상품·구독 운영, API와 웹훅을 활용하는 후보가 될 수 있다. 다만 Play 배포 앱의 인앱 디지털 구독 정책을 대신 충족해 주는 것은 아니다. [스텝페이 개발자 센터](https://developer.steppay.kr/)와 [시작 안내](https://support.steppay.kr/ko/articles/9822317-%EC%8A%A4%ED%85%9D%ED%8E%98%EC%9D%B4-%EC%96%B4%EB%96%BB%EA%B2%8C-%EC%8B%9C%EC%9E%91%ED%95%98%EB%82%98%EC%9A%94)를 정책 검토와 별도로 확인한다.

월 가격은 확정하지 않는다. 초기 조사 범위는 월 2,900~6,900원 정도로 두되 신규 콘텐츠 공급 주기, 고객 지원 비용, 결제 수수료, 사용성 조사와 지불 의향을 확인한 뒤 결정한다. 어르신 사용자의 의도하지 않은 자동 결제를 줄이기 위해 무료 체험은 기본 권장하지 않으며, 도입 시 가격·주기·자동 갱신·해지 방법을 결제 전에 명확히 표시한다.

### 4.4 음성 안내

- 화면의 핵심 질문과 선택 안내 읽기
- `다시 듣기` 버튼
- 느리게/보통 속도
- 음량은 Android 미디어 음량 사용
- 자동 읽기는 기본 끔
- 기기 내 Android TTS 우선, 서버로 문구나 음성 전송 안 함
- TalkBack이 활성화되면 자동 읽기를 끄거나 사용자에게 중복 가능성을 알림
- 모든 음성 기능은 텍스트와 동일한 내용을 보조하며 음성만으로 기능을 제공하지 않음

### 4.5 공지사항·FAQ·문의

- V3 1차는 앱에 포함된 JSON 또는 Markdown으로 공지와 FAQ 제공
- 원격 공지는 운영 필요성이 확인된 뒤 읽기 전용 피드로 전환
- 문의는 이메일 앱 열기 또는 최소 양식으로 시작
- 앱 버전 첨부는 사용자가 확인하고 동의할 때만 사용
- 기기 모델, 광고 ID, 전화번호, 연습 기록은 자동 첨부하지 않음
- 서버 문의를 도입하면 접수 번호로 답변을 확인하고 보유 기간과 삭제 정책을 고지
- 운영자 화면은 원격 공지나 문의 서버를 도입할 때 함께 설계

### 4.7 보호자 기능

연습 현황 요약, 추천 연습, 응원 메시지는 가치가 있지만 계정 연결과 어르신의 명시적 동의가 필요하다. 보호자에게 최근 활동이 그대로 노출되면 감시로 느껴질 수 있고 생활 패턴이 드러날 수 있다. 연결 해제, 공개 범위, 동의 철회, 계정 분쟁 처리까지 필요하므로 V4 이후 별도 연구 대상으로 둔다.

## 6. V3 기본안과 확장안 비교

| 항목 | 기본 권장안 | 확장안 |
|---|---|---|
| 범위 | 게스트 유지, 기기 TTS, 정적 공지·FAQ, 최소 문의, 신규 콘텐츠 2~3개, 미션·배지 확장, 구독 설계 | 회원가입, 동기화, 실결제, 운영자 웹, 보호자 기능 |
| 1인 개발 규모 | 중간, 약 2~4개월 범위 | 매우 큼, 약 6~12개월 이상 가능 |
| 서버 비용 | 거의 없음 | 인증·DB·백업·모니터링·메일 비용 지속 |
| 개인정보 | 현재 수준 유지 가능 | 계정·행동 기록·문의 데이터 처리 필요 |
| 정책 위험 | 낮음 | Play 결제·탈퇴·개인정보 정책 검토 필수 |
| 장애 범위 | 앱 내부로 제한 | 네트워크와 서버 장애가 학습 경험에 영향 |
| 추천 | V3 | 운영 수요와 수익 모델 검증 후 V4 |

기간은 확정 일정이 아니라 기존 테스트를 유지하는 1인 개발의 상대적 추정이다.

## 8. 테스트 전략

- V2의 183개 테스트를 기준선으로 계속 실행한다.
- V2 저장값을 준비한 뒤 V3 최초 실행, 반복 실행, 중단 후 재실행을 검사한다.
- 로그인하지 않은 사용자와 완전 오프라인 상태를 기본 시나리오로 둔다.
- TTS는 가짜 서비스로 호출 문구·순서·중복 방지를 테스트하고 실제 기기에서 속도와 TalkBack 중복을 검사한다.
- 320dp, 아주 큰 글씨, 선명한 화면, TalkBack 순서와 터치 영역을 확인한다.
- 구독 화면은 `free`, `trial`, `active`, `grace`, `expired`, `unavailable` 가짜 상태로만 테스트한다.
- 결제 실패와 서버 장애 테스트는 실제 어댑터를 도입하는 단계에서 필수로 추가한다.
- 업데이트 전후 포인트·횟수·배지·최근 기록·미션·설정이 같은지 스냅샷 비교한다.
- Android 실제 기기에서 TTS 엔진 유무, 백그라운드 복귀, 제조사 글자 배율을 확인한다.

## 10. 사용자가 결정해야 할 사항

1. V3 신규 콘텐츠를 `문자 보내기 + 셀프 계산대`로 확정할지, 길 찾기까지 포함할지
2. 음성 안내의 자동 읽기를 제공할지, 기본값을 항상 끔으로 고정할지
3. 공지를 앱 번들로만 운영할지, V3 중간에 원격 공지로 확장할지
4. 문의를 이메일 연결로 시작할지, 앱 안 최소 양식을 준비할지
5. V3에서 구독 안내 화면까지 만들지, 사용자 조사 뒤로 미룰지
6. 신규 콘텐츠 중 어느 범위까지 무료로 둘지

## 11. 권장 결론

V3는 로컬 중심으로 시작한다. 기존 데이터와 무료 기능을 그대로 유지하고, 기기 내 음성 안내, 정적 FAQ·공지, 최소 문의, 신규 가상 연습 2개, 미션·배지 확장을 우선 구현한다. 구독은 권한 경계와 문구만 설계하고 실제 결제는 Google Play와 스텝페이의 최신 공식 정책을 확인하는 별도 단계로 분리한다. 계정, 클라우드 동기화, 보호자 연결은 개인정보와 운영 역량이 준비된 V4 이후에 재평가한다.

## 12. 연습 포인트 혜택

V3는 포인트 상점이 아니라 **누적 포인트 자동 해제 방식**을 사용한다. 보상을 받아도 포인트는 차감되지 않으며, 기존 7개 콘텐츠와 접근성·힌트·음성 안내는 포인트로 잠그지 않는다.

- 포인트 명칭은 `연습 포인트`로 통일한다.
- 자유 연습 0점, 따라 해보기 10점, 혼자 해보기 20점을 유지한다.
- 오늘의 미션은 혼자 해보기 기본 20점과 추가 10점이며 추가 보상은 하루 최대 30점이다. 미션 3개를 모두 완료하면 기본 보상을 포함해 하루 최대 90점이다.
- 연습 포인트는 현금 가치가 없고 구매·환불·환전·전송할 수 없다.
- 구독 여부에 따라 같은 연습의 포인트 지급량을 바꾸지 않는다.
- 포인트를 직접 판매하거나 구독 결제에 사용하지 않고 구독 포인트 2배도 제공하지 않는다.
- 적극 사용자 90점/일과 완만한 사용자 20~30점/일을 함께 고려한다.
- 초기 권장 기준은 100점 `첫걸음 시작`(`title_first_step`), 300점 `목도리`(`accessory_scarf`), 500점 `세이지 테마`(`theme_sage`), 800점 `꾸준한 연습생`(`title_steady_learner`), 1,200점 `모자`(`accessory_hat`), 1,600점 `하늘색 테마`(`theme_sky`)·`안경`(`accessory_glasses`), 2,000점 `디지털 자신감`(`title_digital_confidence`), 3,000점 `복숭아색 테마`(`theme_peach`)·`가방`(`accessory_bag`), 5,000점 `한걸음 달인`(`title_hangeoreum_master`)·`특별 축하 표정`(`expression_celebration`)이다.
- V3 1차는 칭호 4개, 한걸음이 꾸미기 5종, 기본 아이보리를 포함한 홈 테마 4종, 다음 보상 진행률과 획득 안내를 포함한다.
- 구독이 끝나도 획득한 포인트 보상은 유지한다.
- 실제 상품, 쿠폰, 현금, 환급과 사용자 간 전송은 포함하지 않는다.
- 기존 사용자에게는 현재 포인트에 해당하는 보상을 차감 없이 한 번 소급 지급한다.
- `연습 기록 초기화` 시 포인트에서 파생된 칭호·장식·테마도 초기화하고 글자 크기·선명한 화면·온보딩·음성 안내·일반 앱 설정은 유지한다.

홈에는 낮은 포인트·다음 보상 요약과 `나의 보상 보기`를, 내 정보에는 현재 단계·칭호·다음 보상·획득 꾸미기와 `전체 보상 보기`를 둔다. 전체 보상 화면은 `획득`, `적용 중`, `아직 획득 전`, 필요한 포인트와 `사용하기` 또는 `적용하기`를 문구로 구분한다.

이 기준은 V3 초기 권장안이며 사용성 시험 뒤 조정할 수 있다. 보상 ID는 표시 이름이나 기준이 바뀌어도 유지하고, 이미 획득한 보상은 기준 변경이나 구독 종료를 이유로 회수하지 않는다. 한 기준에 두 보상이 있으면 각각 별도 ID를 사용한다.

기준별 예상 도달 기간, 화면, 저장 모델, 마이그레이션과 테스트는 [V3 포인트 혜택 설계](V3_포인트_혜택_설계.md)에 정리한다.
