# V3 포인트 소급 지급 구현

## 1. 범위

이 단계는 기존 `digital_confidence_points`를 보존하면서 현재 점수 이하의 활성 보상을 한 번 소급 지급하고, 이후 실제 포인트 증가 뒤 신규 기준 보상을 자동 해제한다. 포인트 차감, 보상 화면, 홈·내 정보 변경, 캐릭터 장식·테마 렌더링과 축하 팝업은 포함하지 않는다.

## 2. schema와 revision

- schema version: `2`
- revision 1: `v3_foundation_1`
- revision 2: `v3_reward_backfill_2`

revision 2는 포인트를 0 이상으로 정규화해 카탈로그의 활성 보상과 기존 획득 ID를 합집합으로 저장한다. 신규 획득 ID에는 한 실행에서 같은 UTC 시각을 기록하고 기존 시각은 덮어쓰지 않는다. 성공 후 소급 지급 완료, completed revision, schema 2를 기록하고 migration pending을 제거한다.

## 3. 소급 지급 규칙

| 포인트 | 획득 결과 |
|---:|---|
| 0~99 | 없음 |
| 100~299 | `title_first_step` |
| 300~499 | 위 보상 + `accessory_scarf` |
| 1,600 | 1,600점 이하 7개 |
| 5,000 이상 | 활성 보상 12개 전체 |

160점 사용자는 `title_first_step`만 획득하고 160점은 그대로 유지한다. 여러 기준을 이미 넘었으면 신규 ID를 한 저장 후보와 한 pending 묶음으로 처리한다.

## 4. RewardUnlockService

`RewardUnlockService`는 UI와 라우팅에 의존하지 않는다.

- 음수 포인트를 0으로 정규화
- 활성 카탈로그와 기존 획득 ID 비교
- 신규 ID를 카탈로그 순서로 반환
- 서비스 인스턴스 안의 요청 직렬화
- 기존 ID·시각·축하·선택·미래 ID 보존
- 미래 데이터·카탈로그 버전의 쓰기 중단
- 저장 실패의 구조화 결과 반환
- 획득 ID와 축하 완료 ID 차이의 pending 보상 조회

pending 조회는 현재 카탈로그에 알려진 보상만 안정 순서로 반환한다. 이미 축하 완료된 ID와 알 수 없는 미래 ID는 UI 후보에서 제외한다. 현재 카탈로그에 남아 있는 비활성 보상을 과거에 획득했다면 회수하지 않으며 pending 안내 대상에는 유지한다.

## 5. 앱 시작과 포인트 증가

앱은 마이그레이션 성공 후 Provider 생성 전에 한 번 reconciliation한다. 마이그레이션 이후 포인트 저장과 보상 저장 사이에서 앱이 종료됐거나 일부 보상 키가 손상된 경우 누락 ID만 복구한다. 이미 최신이면 쓰지 않고 pending을 소비하지 않는다.

`LearningProgressProvider`는 따라 해보기 10점, 혼자 해보기 20점, 병원 세부 업무, 오늘의 미션 추가 10점을 기존 중복 방지 뒤 공통 `_awardPoints` 경로로 저장한다. 포인트 저장 성공 후 최신 총점으로 서비스를 호출한다. 보상 저장이 실패해도 지급된 포인트를 되돌리지 않으며 다음 앱 시작 reconciliation이 복구한다. 자유 연습 0점과 중복 완료에는 호출할 새 포인트가 없다.

## 6. 초기화

연습 기록 초기화는 포인트, 완료 횟수, 배지, 최근 기록, 미션 상태와 모든 `v3_reward_*` 상태 키를 제거한다. schema version 2와 completed revision, 글자 크기, 화면 대비, 온보딩과 일반 설정은 유지한다.

초기화 직후 0점 reconciliation은 보상 키를 다시 만들지 않는다. revision 2는 이미 완료됐으므로 재실행하지 않지만, 이후 100점에 다시 도달하면 `title_first_step`을 새로 획득할 수 있다.

## 7. 실패와 미래 버전

보상 저장은 전체 후보 JSON을 pending에 먼저 기록하고 개별 키를 쓴 뒤 재검증한다. 쓰기 중 종료되면 다음 `load()`가 후보를 복구한다. migration의 각 체크포인트에서 중단돼도 revision 2를 멱등 재실행한다.

현재보다 높은 reward data/catalog version 또는 schema version은 덮어쓰거나 낮추지 않는다. 실패를 이유로 전체 보상 상태나 V2 데이터를 삭제하지 않으며 알 수 없는 미래 보상 ID도 보존한다.

## 8. 테스트와 현재 제한

0·99·100·160·300·1,600·5,000점 이상, 음수, 반복 실행, 동시 요청, 기존 상태 합집합, 미래 ID, pending 정렬, 저장 실패 복구, 초기화 후 재획득과 기존 포인트 지급 회귀를 자동 테스트한다.

현재는 보상 화면이나 축하 표현이 없다. 신규 획득은 자동으로 축하 완료 처리되지 않아 다음 단계에서 한 번 안내할 수 있다. 다음 단계는 `V3 나의 보상 화면 및 홈 진행 요약 구현`이다.
