# 한걸음 디지털 V3 연습 포인트 혜택 설계

## 1. 목적과 원칙

연습 포인트는 사용자가 연습을 이어 온 과정을 눈에 보이게 만드는 앱 내부의 비금전성 성장 지표다. 현금, 전자화폐, 쿠폰, 환급 가능한 자산이 아니며 구매·전송·환전할 수 없다.

- 자유 연습 0점, 따라 해보기 10점, 혼자 해보기 20점, 오늘의 미션 20점+10점 정책을 유지한다.
- 오늘의 미션 추가 보상은 하루 최대 30점이며 미션 3개를 모두 완료하면 기본 점수를 포함해 하루 90점이다.
- 같은 연습의 포인트는 구독 여부와 관계없이 동일하다.
- 기존 포인트 키와 누적값을 변경하거나 차감하지 않는다.
- 큰 글씨, 선명한 화면, 힌트, 음성 안내와 필수 학습은 보상이나 포인트로 잠그지 않는다.
- 기존 7개 무료 콘텐츠를 포인트로 잠그지 않는다.
- 보상을 적용하지 않아도 학습 기능에 불이익이 없다.
- 구독 종료 뒤에도 포인트로 획득한 보상을 회수하지 않는다.

## 2. 포인트를 모아야 하는 이유

포인트의 목적은 경쟁이나 소비가 아니라 다음을 돕는 것이다.

1. 연습이 쌓이고 있다는 감각 제공
2. 너무 멀지 않은 다음 목표 제공
3. 한걸음이와 홈 화면을 자신의 취향으로 바꾸는 즐거움 제공
4. 내 정보에서 지난 성장을 차분하게 돌아볼 수 있게 함

순위, 다른 사용자와의 비교, 연속 접속을 강요하는 손실 표현은 사용하지 않는다.

## 3. 누적 해제와 포인트 상점 비교

| 항목 | 누적 해제 | 포인트 상점 |
|---|---|---|
| 포인트 차감 | 없음 | 구매 시 차감 |
| 사용자 이해 | 기준을 넘으면 자동 획득 | 잔액·가격·구매 개념 필요 |
| 기존 데이터 호환 | 현재 총점만으로 계산 가능 | 초기 잔액과 과거 사용 내역 필요 |
| 오류 처리 | 중복 해제 방지만 필요 | 취소, 환불, 중복 구매, 잔액 복원 필요 |
| 초기화 | 총점과 해제 목록을 함께 초기화 | 잔액과 거래 원장을 함께 처리 |
| 어르신 오해 위험 | 낮음 | 포인트가 사라졌다는 손실감 가능 |
| 향후 동기화 | 해제 ID 합집합으로 비교적 단순 | 거래 원장과 서버 검증 필요 |

V3는 **누적 해제 방식**을 사용한다. 보상을 받아도 보유 포인트는 줄지 않는다. 포인트 상점은 사용자 조사에서 명확한 수요가 확인되기 전에는 도입하지 않는다.

## 4. 포인트 기준 계산

오늘의 미션 3개를 모두 완료하면 하루 90점을 얻는다. 매일 전부 완료하는 사용자만 기준으로 잡으면 보상이 너무 빨리 끝나므로 다음 두 패턴을 함께 본다.

- 적극 사용자: 하루 90점
- 완만한 사용자: 하루 평균 20~30점

| 누적 점수 | 적극 사용자 예상 | 하루 30점 | 하루 20점 | 권장 보상과 안정 ID |
|---:|---:|---:|---:|---|
| 100 | 2일 | 4일 | 5일 | 칭호 `첫걸음 시작` (`title.first_step`) |
| 300 | 4일 | 10일 | 15일 | 목도리 (`decor.neck.sage_scarf`) |
| 500 | 6일 | 17일 | 25일 | 세이지 홈 테마 (`theme.home.sage`) |
| 800 | 9일 | 27일 | 40일 | 칭호 `꾸준한 연습생` (`title.steady_learner`) |
| 1,200 | 14일 | 40일 | 60일 | 모자 (`decor.head.practice_hat`) |
| 1,600 | 18일 | 54일 | 80일 | 하늘색 홈 테마 (`theme.home.sky`), 안경 (`decor.face.round_glasses`) |
| 2,000 | 23일 | 67일 | 100일 | 칭호 `디지털 자신감` (`title.digital_confidence`) |
| 3,000 | 34일 | 100일 | 150일 | 복숭아색 홈 테마 (`theme.home.peach`), 가방 (`decor.side.small_bag`) |
| 5,000 | 56일 | 167일 | 250일 | 칭호 `한걸음 달인` (`title.han_geoleum_master`), 특별 축하 표현 (`expression.special_celebration`) |

첫 보상은 완만한 사용자도 4~5회 연습일 안에 경험할 수 있고, 마지막 보상은 적극 사용자에게도 약 8주가 필요하다. 이 값은 V3 초기 권장안이며 실제 사용성 시험에서 첫 보상 도달 시간, 30일 유지율이 아니라 이해도와 부담감을 중심으로 조정할 수 있다. 일일 포인트 상한은 이번 설계에 새로 추가하지 않는다.

보상 ID는 표시 이름이나 기준 포인트가 바뀌어도 유지한다. 기준이 낮아지면 새로 충족한 사용자에게 해제하되 이미 획득한 보상은 회수하지 않는다. 한 기준에서 보상이 두 개인 경우에도 각각 고유 ID를 사용한다.

## 5. 보상 종류

### 5.1 한걸음이 꾸미기

현재 한걸음이는 `CustomPainter`가 몸, 새싹, 얼굴과 감정 효과를 비율 좌표로 그린다. 다음 방식으로 외부 이미지 없이 확장할 수 있다.

- `HanGeoleumDecoration` 모델을 painter에 전달
- 모자: 머리 위 레이어
- 목도리: 얼굴 아래 레이어
- 안경: 눈 위 레이어
- 작은 가방: 몸 옆 레이어
- 특별 표정: 기존 `HanGeoleumMood`와 충돌하지 않는 축하 상태 변형

장식은 크기에 비례해 그리며 52dp 캐릭터에서도 얼굴을 가리지 않아야 한다. 모자·안경처럼 같은 영역을 쓰는 장식은 슬롯별 하나만 적용한다. V3 1차는 목도리, 모자, 안경, 가방 네 종을 권장한다. 계절 장식은 카탈로그만 준비하고 원격 기간 제한이나 놓치면 사라지는 보상은 도입하지 않는다.

### 5.2 화면 꾸미기

- 기본 아이보리
- 아주 연한 세이지
- 아주 연한 하늘색
- 아주 연한 복숭아색

테마는 배경과 작은 장식만 바꾸며 본문 색, 대비, 버튼 의미색은 기존 디자인 토큰을 따른다. 선명한 화면에서는 장식 배경을 약화하거나 끄고 대비 토큰을 우선한다. 완료 축하는 짧은 정적 장식 또는 줄어든 움직임으로 제공하고 빠른 반짝임과 자동 반복 애니메이션은 사용하지 않는다.

### 5.3 칭호

- 첫걸음 시작
- 꾸준한 연습생
- 디지털 자신감
- 한걸음 달인

칭호는 한 개를 직접 선택하며 내 정보에 표시한다. `주문 연습 전문가` 같은 콘텐츠 숙련 칭호는 콘텐츠별 완료 조건을 정의하는 후속 단계로 둔다.

### 5.4 기념 배지

기존 8개 첫 완료 배지는 ID와 의미를 유지한다. V3 기념 배지는 별도 ID 영역을 사용한다.

- `milestone.points.*`: 누적 포인트
- `milestone.streak.*`: 연속 연습
- `mastery.content.*`: 콘텐츠별 숙련
- `milestone.daily_mission.*`: 오늘의 미션 완주
- `milestone.weekly_goal.*`: 주간 목표

V3 1차에서는 칭호·꾸미기·테마와 역할이 겹치는 포인트 배지를 추가하지 않는다. 연속·주간 배지는 사용자가 쉬는 날 손해를 봤다고 느낄 수 있으므로 문구와 복구 정책을 별도 설계한 뒤 도입한다.

### 5.5 성장 기록

- 현재 누적 연습 포인트
- 현재 성장 단계
- 다음 보상과 필요한 포인트
- 지금까지 획득한 칭호·꾸미기·테마
- 획득 날짜
- 현재 적용 상태

다른 사용자 수치와 순위를 표시하지 않는다.

## 6. V3 1차 보상 범위

- 누적 포인트 단계 9개
- 칭호 4개
- 한걸음이 꾸미기 4종
- 홈 테마 3종
- 다음 보상 진행률
- 여러 보상을 묶어 보여주는 해제 안내
- 내 정보의 `나의 보상`
- 칭호·장식·테마 선택
- 획득한 보상과 미획득 보상 목록

실물 상품, 기프티콘, 현금, 제휴 쿠폰은 포함하지 않는다.

## 7. 보상 해제 처리

### 7.1 순서

1. 기존 완료 보상 로직이 포인트 지급을 성공적으로 마친다.
2. 지급 전후 포인트와 보상 카탈로그 버전을 `RewardEvaluator`에 전달한다.
3. 기준 이하의 보상 중 아직 획득하지 않은 ID를 계산한다.
4. 획득 ID와 시각을 저장한다.
5. 새 ID를 하나의 축하 묶음으로 저장한다.
6. 완료 화면 뒤에 한 번만 보상 안내를 연다.
7. 사용자가 닫거나 적용하면 해당 ID의 안내 완료를 기록한다.

포인트 지급 성공이 보상 해제보다 먼저 확정되어야 한다. 보상 저장 실패가 기존 포인트를 되돌려서는 안 되며 다음 실행에서 총점을 기준으로 다시 복구한다.

### 7.2 중복 방지

- 보상 ID를 고유 키로 사용한다.
- 메모리 내 평가 잠금으로 빠른 동시 요청을 직렬화한다.
- 완료 화면 재진입은 이미 획득한 ID를 다시 생성하지 않는다.
- 축하 묶음에는 지급 세션 토큰과 카탈로그 버전을 기록한다.
- 한 번에 여러 기준을 넘으면 한 화면에서 목록으로 안내한다.
- 안내 도중 앱이 종료되면 다음 실행에서 한 번 다시 보여주고, 완료 기록 뒤에는 반복하지 않는다.

### 7.3 기존 사용자 소급 지급

V3 최초 실행에서 현재 총점을 읽고 기준 이하의 모든 보상을 자동 획득한다.

예: 기존 160점 사용자는 `첫걸음 시작`을 획득하고 160점은 그대로 유지한다. 소급 보상은 한 묶음으로 한 번만 알린다. 기존 배지와 최근 기록에는 쓰지 않는다.

소급 처리 완료는 카탈로그 버전 단위로 저장한다. 이후 앱 버전에 새 낮은 기준 보상이 추가되면 해당 보상만 다시 평가할 수 있다. 표시 이름이나 기준이 바뀌어도 안정 ID가 같으면 중복 보상을 만들지 않는다.

## 8. 기록 초기화 정책

### 비교

| 안 | 장점 | 단점 |
|---|---|---|
| 포인트·배지·보상 모두 초기화 | 현재 `연습 기록 초기화` 의미와 일치, 0점 상태가 명확 | 꾸미기도 사라져 아쉬움이 생길 수 있음 |
| 포인트·기록만 초기화하고 꾸미기 유지 | 획득한 꾸미기 소유감 유지 | 0점인데 고점수 보상을 가진 모순, 초기화 범위 이해 어려움 |

### 추천

첫 번째 안을 권장한다. 현재 초기화가 포인트, 완료 횟수, 배지, 최근 기록, 미션 상태를 처음으로 돌리는 기능이므로 포인트에서 파생된 칭호·꾸미기·테마도 함께 초기화하는 편이 일관적이다.

초기화 확인 문구에는 다음을 명시한다.

- 초기화: 포인트, 완료 횟수, 기존·V3 배지, 최근 기록, 오늘의 미션 상태, 포인트 칭호·장식·테마
- 유지: 글자 크기, 선명한 화면, 온보딩 완료, 음성 안내, 일반 앱 설정과 향후 구독 혜택

적용 중인 장식·칭호·테마는 기본값으로 되돌린다. 초기화 직후 0점을 기준으로 보상을 재평가하며 어떤 보상도 자동 복구하지 않는다.

## 10. SharedPreferences 저장 구조

기존 포인트 키 `digital_confidence_points`를 그대로 사용한다.

| 신규 키 후보 | 형식 | 용도 |
|---|---|---|
| `v3_reward_schema_version` | int | 보상 저장 구조 버전 |
| `v3_reward_migration_version` | int | 소급 마이그레이션 완료 버전 |
| `v3_reward_state_json` | JSON String | 카탈로그 버전, 획득 ID·시각, 축하 완료, 적용 칭호·슬롯별 장식·홈 테마를 담는 정본 |
| `v3_reward_state_pending_json` | JSON String | 정본 교체 전 검증하는 후보 상태 |

상태 변경은 현재 정본을 읽어 새 revision의 후보 JSON을 만들고 pending 키에 기록한 뒤 다시 읽어 검증한다. 검증에 성공한 후보만 `v3_reward_state_json`으로 교체하고 마지막에 스키마·마이그레이션 버전을 올린 뒤 pending을 제거한다. 중간 종료 시 기존 정본을 유지하며 다음 실행에서 유효한 revision을 골라 재시도한다. 총점과 정적 카탈로그로 획득 ID를 재구성할 수 있고, 알 수 없거나 미획득인 선택 ID는 기본값으로 복구한다.

SharedPreferences는 수십 개의 고정 보상 ID와 작은 선택 상태에는 충분하다. 다음 조건이 생기면 Drift/SQLite 같은 로컬 DB를 검토한다.

- 보상·획득 이벤트가 수백~수천 건으로 증가
- 포인트 거래 원장이나 취소 이력이 필요
- 계정 동기화를 위한 오프라인 이벤트 큐가 필요
- 여러 카탈로그와 기간형 이벤트를 검색해야 함
- 여러 키를 하나의 트랜잭션으로 갱신해야 함

## 11. 화면 설계

### 11.1 홈

기존 콘텐츠보다 먼저 강조하지 않는 한 줄 요약 영역을 둔다.

- `연습 포인트 460점`
- `다음 보상까지 40점`
- 진행 바
- 다음 보상의 작은 아이콘과 이름

전체 영역을 누르면 내 정보의 `나의 보상`으로 이동한다. 기본 높이를 낮게 유지하고 320dp·아주 큰 글씨에서는 텍스트와 진행률을 세로로 배치한다.

### 11.2 내 정보

- 현재 성장 단계와 선택한 칭호
- 현재 한걸음이 미리보기
- `꾸미기`, `칭호`, `홈 테마` 탭 또는 구분 목록
- 획득 보상: 적용/해제 버튼
- 미획득 보상: 잠금 문구와 `N점 더 필요`
- 획득 날짜

미획득 목록도 내용을 숨기지 않고 다음 목표로 보여준다. 선택 변경은 포인트를 차감하지 않는다.

### 11.3 보상 획득 안내

- 축하하는 한걸음이
- `새 보상을 받았어요`
- 새 보상 이름과 설명
- 여러 개면 간결한 목록
- 주 버튼 `사용해 보기`
- 보조 버튼 `나중에 선택하기`
- 작은 안내 `연습 포인트로 열린 앱 안의 꾸미기 보상이에요.`

실제 금전 가치가 없다는 안내는 명확하되 축하보다 반복적으로 크게 표시하지 않는다.

## 12. 접근성

- 장식 이름, 획득 여부, 선택 상태를 한 문장으로 읽는다.
- 색상만으로 잠금·선택 상태를 구분하지 않고 아이콘과 문구를 함께 쓴다.
- 미획득 보상은 `모자, 미획득, 240점 더 필요`처럼 읽는다.
- 진행률은 `다음 보상까지 500점 중 460점, 92퍼센트`로 제공한다.
- 캐릭터 미리보기는 주변 텍스트와 중복되면 Semantics에서 제외한다.
- 48dp 터치 영역과 주요 버튼 56dp를 유지한다.
- 애니메이션 줄이기 설정 또는 Android 접근성 설정을 존중하고 축하 효과를 정적으로 대체한다.
- 선명한 화면에서 테마가 텍스트·버튼 대비를 변경하지 못하게 한다.
- 보상을 적용하지 않아도 모든 연습과 도움 기능을 동일하게 사용할 수 있다.

- 같은 ID 중복 해제 방지

- 동시에 들어온 완료 요청

- 기록 초기화 뒤 보상과 선택 초기화
- 구독 종료 뒤 보상 유지
- 카탈로그 버전 변경과 ID 호환
- 손상된 JSON을 총점과 카탈로그로 복구

- 줄어든 애니메이션
- 홈 마지막 콘텐츠와 하단 탭 가림 없음

## 14. 구독과의 관계

- 같은 연습의 점수는 무료·구독 사용자에게 동일하다.
- 포인트 보상은 구독 종료 뒤에도 유지한다.
- 구독 전용 콘텐츠에서 얻은 정상 포인트도 구독 종료 뒤 차감하지 않는다.
- 구독 상태를 보상 해제 조건으로 사용하지 않는다.
- 접근성, 힌트, 음성 기본 기능을 포인트나 구독으로 잠그지 않는다.
- 유료 장식이 필요해지더라도 포인트 장식과 명확히 분리하고 혼동되는 이중 가격을 만들지 않는다.

## 15. 향후 실물·제휴 보상 검토 사항

V3에는 포함하지 않는다. 향후 검토 시 다음을 별도 법률·세무·운영 검토한다.

- 포인트의 양도·환급·제3자 사용 가능성에 따른 전자금융 규제 여부
- 쿠폰 발행자, 유효기간, 환불, 사용 제한과 소비자 분쟁 기준
- 경품·기타소득과 원천징수·지급명세 의무 여부
- 이름, 연락처, 배송지 등 개인정보 최소 수집과 파기
- 계정 탈취, 다중 기기, 자동화 완료, 중복 쿠폰의 부정 사용 방지
- 제휴사 정산, 재고, 만료, 고객 지원, 취소 비용
- 앱 심사 정책과 프로모션 표시 문구

현금성이나 제3자 사용 가치가 생기면 현재의 단순 연습 포인트와 법적 성격이 달라질 수 있다. 구현 전에 [전자금융거래법](https://www.law.go.kr/LSW/lsInfoP.do?lsId=009285), 개인정보 보호법, 소득세법과 공정거래위원회 소비자 기준을 최신 상태로 확인하고 전문 검토를 받아야 한다.
