# 카페 키오스크 V2 설계

## 1. 문서 목적

한걸음 디지털 V1의 학습 기록과 보상 체계를 유지하면서, 카페 학습을 실제 사용 순서에 가까운 **연습용 가상 카페 키오스크**로 확장하기 위한 설계 문서다.

V2도 실제 주문, 결제, 계정, 서버, 데이터베이스 또는 외부 API와 연결하지 않는다. 실제 브랜드명, 로고, 메뉴 화면도 복제하지 않는다.

## 2. 현재 V1 구조 분석

### 화면과 라우팅

현재 카페 학습은 다음 고정 라우트로 구성된다.

| 경로 | 화면 | 역할 |
| --- | --- | --- |
| `/cafe` | `CafeStartPage` | 따라 해보기·혼자 해보기 선택 |
| `/cafe/mission` | `CafeMissionPage` | 혼자 해보기 목표 안내 |
| `/cafe/practice` | `CafePracticePage` | 매장 식사·포장 선택 |
| `/cafe/practice/step-2` | `CafeStepTwoPage` | 음료 선택 |
| `/cafe/practice/step-3` | `CafeStepThreePage` | 온도 선택 |
| `/cafe/practice/step-4` | `CafeStepFourPage` | 주문 확인 |
| `/cafe/complete` | `CafeCompletePage` | 보상 저장과 완료 안내 |

상세 화면은 하단 탭 바깥에 있으며, 각 단계는 `context.go()`로 명시적인 이전·다음 경로를 사용한다.

### 상태와 저장

`LearningProgressProvider`가 다음 상태를 관리한다.

- 학습 모드: `CafeLearningMode.guided`, `CafeLearningMode.solo`
- 현재 선택: 매장/포장, 음료, 온도
- 따라 해보기·혼자 해보기 완료 횟수
- 포인트, 첫 완료 배지, 익숙해요 배지
- 최근 연습 기록
- 모드별 세션 보상 지급 여부

완료 보상은 `completeCafeLearning()`을 단일 진입점으로 사용한다. 메모리 플래그와 SharedPreferences 세션 키를 함께 확인하므로 완료 화면 재진입, 반복 클릭, Provider 재생성 뒤에도 중복 지급을 막는다.

### 혼자 해보기 판정

`CafeOrderMission`이 매장/포장, 음료, 온도의 목표값과 단계별 판정을 담당한다. 목표와 다른 선택은 현재 단계에 머물고 긍정 안내와 힌트를 제공한다.

### 재사용 가능한 V1 위젯

- `LearningModeCard`: 시작 화면의 모드 선택
- `LearningStepLayout`: 상단 뒤로가기, 진행 상태, 스크롤, 하단 보조 동작
- `ProgressHeader`: 단계 문구와 진행 바
- `KioskPanel`: 가상 주문 화면의 기본 외곽 패널
- `LearningChoiceCard`: 큰 선택 항목과 따라 해보기 강조 상태
- `LearningSummaryCard`: 영수증·장바구니 형태의 선택 결과
- `LearningCompletionLayout`: 완료 문구, 포인트·배지, 다시 하기·홈 이동
- `LargeActionButton`: 큰 기본·보조 동작 버튼

V2는 위 위젯의 접근성 규칙과 색상 체계를 유지하되, 메뉴 그리드와 장바구니처럼 역할이 다른 UI를 억지로 `LearningChoiceCard`에 넣지 않는다.

## 3. V1과 V2 비교

| 구분 | V1 | V2 목표 |
| --- | --- | --- |
| 메뉴 선택 | 텍스트 중심 세로 선택 카드 | 카테고리와 메뉴 카드가 있는 가상 메뉴판 |
| 주문 상태 | 단계 화면 내부 선택값 | 모든 화면에서 유지되는 주문 세션과 장바구니 개수 |
| 옵션 | 매장/포장, 음료, 온도 | 온도, 크기, 매장/포장을 한 항목씩 선택 |
| 확인 | 단일 영수증 카드 | 메뉴·옵션·수량·가상 가격을 포함한 장바구니 |
| 결제 | 확인 후 바로 완료 | 실제 거래가 없는 연습용 결제 확인 화면 |
| 보상 | 기존 포인트·횟수·배지·최근 기록 | V1 저장 키와 완료 API를 그대로 사용 |
| 혼자 해보기 | 고정 미션 정답 판정 | 메뉴와 옵션을 포함하는 미션 판정으로 확장 |

## 4. V2 사용자 흐름

### 공통 진입

1. 카페 시작 화면에서 `따라 해보기` 또는 `혼자 해보기`를 선택한다.
2. 혼자 해보기는 미션 안내 화면에서 목표 주문을 확인한다.
3. `카페 주문` 화면으로 이동한다.

### 주문 흐름

1. **메뉴 고르기**
   - 상단에 `카페 주문`, 진행 상태, 장바구니 버튼과 선택 개수를 표시한다.
   - `커피`, `차`, `음료` 카테고리를 탭으로 선택한다.
   - 메뉴 카드는 아이콘 또는 단순 도형, 한 줄 메뉴명, 가상 가격을 표시한다.
2. **온도 고르기**
   - 선택한 메뉴를 상단에 요약한다.
   - `따뜻하게`, `차갑게` 중 가능한 옵션만 크게 보여준다.
3. **크기 고르기**
   - `보통`, `크게`처럼 쉬운 한국어를 먼저 사용하고 보조 설명에만 크기 정보를 둔다.
4. **이용 방법 고르기**
   - `매장에서 먹을게요`, `포장할게요`를 선택한다.
5. **장바구니 확인**
   - 메뉴, 온도, 크기, 매장/포장, 수량, 가상 가격을 표시한다.
   - 수량은 큰 빼기·더하기 버튼으로 조절하고 최소 1개를 유지한다.
   - `주문 확인하기`로 다음 화면에 이동한다.
6. **연습용 결제 확인**
   - `실제 결제가 진행되지 않는 연습 화면이에요.`를 명확히 표시한다.
   - 카드번호, 계좌, 개인정보를 입력하지 않는다.
   - `연습 주문 완료하기`를 누르면 기존 완료 화면으로 이동한다.
7. **완료**
   - 기존 포인트, 완료 횟수, 배지, 최근 기록 저장 방식을 사용한다.
   - 실제 주문이 전송되지 않았음을 다시 안내한다.

### 따라 해보기

- 현재 단계의 추천 선택만 세이지색 안내로 부드럽게 표시한다.
- 메뉴 카테고리와 장바구니 등 새 조작에는 짧은 안내 문구를 제공한다.
- 선택 이후에는 다음 중요한 선택으로 이동한다.

### 혼자 해보기

- 미션 예시: `포장 · 아이스 아메리카노 · 보통 크기 1잔`.
- 정답 메뉴나 옵션을 미리 강조하지 않는다.
- 다른 선택은 현재 화면에 머물며 긍정 안내와 `힌트 보기`를 제공한다.
- 힌트는 감점 없이 반복해서 확인할 수 있다.

## 5. 화면 설계

### 공통 상단 `CafeKioskHeader`

- 제목: `카페 주문`
- 현재 진행 상태: `메뉴 고르기`, `옵션 고르기`, `주문 확인` 등
- 장바구니 아이콘과 `N개` 텍스트
- 아이콘 버튼 최소 48dp, 접근성 라벨 `장바구니 보기`
- 320dp·아주 큰 글씨에서는 제목/상태와 장바구니 영역을 세로로 배치

### 메뉴 화면 `CafeMenuPage`

- `CafeCategoryTabs`: 가로 공간이 부족하면 `Wrap` 또는 스크롤 없는 세로형 세그먼트 사용
- `CafeMenuCard`: 최소 높이 112dp, 메뉴명·가상 가격·아이콘 표시
- 넓은 화면은 2열, 320dp 또는 큰 글씨는 1열
- 메뉴명은 가능한 한 한 줄, 큰 글씨에서는 자연스러운 2줄까지 허용

초기 가상 메뉴 후보:

| 카테고리 | 메뉴 | 가상 가격 |
| --- | --- | ---: |
| 커피 | 아메리카노 | 3,000원 |
| 커피 | 카페라테 | 3,500원 |
| 차 | 유자차 | 3,500원 |
| 차 | 녹차 | 3,000원 |
| 음료 | 레몬 음료 | 3,500원 |
| 음료 | 우유 | 2,500원 |

### 옵션 화면 `CafeOptionPage`

- 한 화면에는 `온도`, `크기`, `매장/포장` 중 하나만 표시한다.
- 공통 `CafeOptionCard`로 선택 전·선택됨·따라 해보기 권장 상태를 구분한다.
- 현재 주문 요약을 작은 고정 카드로 표시하되 선택 영역보다 강하게 보이지 않게 한다.

### 장바구니 화면 `CafeCartPage`

- `CafeCartItemCard`: 메뉴명, 옵션, 수량, 단가와 합계를 표시한다.
- `CafeQuantityStepper`: 빼기, 현재 수량, 더하기를 각각 최소 48dp로 제공한다.
- 총액에는 `연습용 금액` 라벨을 붙인다.
- 비어 있는 장바구니에서는 메뉴 화면으로 돌아가는 큰 버튼을 제공한다.

### 연습용 결제 화면 `CafePracticePaymentPage`

- 주문 요약과 가상 총액을 표시한다.
- 실제 결제가 아님을 화면 상단과 완료 버튼 가까이에 표시한다.
- 결제 수단 선택이나 개인정보 입력은 구현하지 않는다.

### 완료 화면

- `LearningCompletionLayout`을 그대로 재사용한다.
- `completeCafeLearning()` 호출 구조와 보상 지급 시점을 유지한다.
- 최근 기록 상세에 주문 메뉴를 넣는 기능은 기존 데이터 호환성을 확인한 뒤 선택적으로 추가한다.

## 6. 새 상태 모델 제안

V2 주문 진행 상태는 거대한 `LearningProgressProvider`에 바로 추가하지 않고 별도 `CafeOrderProvider`로 분리하는 것을 권장한다. 학습 성과는 기존 Provider, 현재 주문은 새 Provider가 담당한다.

```dart
enum CafeCategory { coffee, tea, beverage }
enum CafeTemperature { hot, iced }
enum CafeSize { regular, large }
enum CafeDineOption { dineIn, takeout }
enum CafeOrderStage { menu, temperature, size, dineOption, cart, payment }

class CafeMenuItem {
  final String id;
  final CafeCategory category;
  final String name;
  final int practicePrice;
  final IconData icon;
  final Set<CafeTemperature> temperatures;
}

class CafeCartItem {
  final CafeMenuItem menu;
  final CafeTemperature temperature;
  final CafeSize size;
  final CafeDineOption dineOption;
  final int quantity;
}

class CafeOrderSession {
  final CafeLearningMode mode;
  final CafeOrderStage stage;
  final CafeCategory category;
  final CafeMenuItem? selectedMenu;
  final CafeTemperature? temperature;
  final CafeSize? size;
  final CafeDineOption? dineOption;
  final List<CafeCartItem> cart;
}
```

### 상태 책임

`CafeOrderProvider`:

- 현재 카테고리·메뉴·옵션·수량·장바구니
- 현재 주문 단계와 뒤로가기 시 선택값 유지
- 따라 해보기 권장 항목과 혼자 해보기 미션 비교
- 주문 세션 초기화

기존 `LearningProgressProvider`:

- 학습 모드 호환
- 포인트·완료 횟수·배지·최근 기록
- SharedPreferences 보상 세션 키
- `completeCafeLearning()` 중복 지급 방지

### 저장 원칙

- 첫 구현에서는 V2 주문 세션을 메모리에만 유지해 저장 구조 변경 위험을 줄인다.
- 앱 프로세스 재시작 시 진행 중 화면에 직접 복원하려면, 이후 `cafe_v2_session` 단일 JSON 키와 스키마 버전을 추가한다.
- 기존 `cafe_*` 포인트·완료·배지·보상 키는 이름과 의미를 변경하지 않는다.
- 저장된 세션이 없거나 손상되면 카페 시작 화면으로 안전하게 이동한다.

## 7. 라우트 제안

V1 라우트를 즉시 교체하지 않고 V2를 병렬 경로로 추가해 회귀 테스트 후 진입점만 전환한다.

```text
/cafe/v2/menu
/cafe/v2/options/temperature
/cafe/v2/options/size
/cafe/v2/options/dine-option
/cafe/v2/cart
/cafe/v2/payment
```

완료는 기존 `/cafe/complete`를 재사용한다. V2 세션이 없는데 옵션·장바구니 경로로 직접 들어오면 `/cafe` 또는 `/cafe/v2/menu`로 보낸다.

## 8. 공통 위젯 후보

새 위젯은 카페 V2 전용으로 먼저 검증하고, 다른 학습에서 실제로 필요할 때만 공통 영역으로 승격한다.

- `CafeKioskShell`: 크림 배경, 상단 상태, 장바구니, 스크롤·SafeArea
- `CafeKioskHeader`: 제목, 진행 상태, 장바구니 개수
- `CafeCategoryTabs`: 큰 카테고리 선택
- `CafeMenuCard`: 메뉴 아이콘, 이름, 연습용 가격
- `CafeSelectedOrderSummary`: 현재 메뉴와 옵션 요약
- `CafeOptionCard`: 온도·크기·이용 방법 선택
- `CafeCartItemCard`: 장바구니 항목
- `CafeQuantityStepper`: 접근성 수량 조절
- `PracticePriceText`: 모든 가상 금액에 동일한 표기 적용
- `PracticeOnlyNotice`: 실제 주문·결제가 아니라는 공통 안내

기존 `ProgressHeader`, `LearningCompletionLayout`, `LearningSummaryCard`, `LargeActionButton`은 그대로 재사용한다.

## 9. 접근성 및 반응형 기준

- 기본 본문 20sp 수준, 주요 동작 24sp 수준 유지
- 모든 터치 영역 최소 48dp, 주요 버튼 최소 56dp
- 메뉴·옵션 카드는 전체 영역을 터치 가능하게 구성
- 320dp·아주 큰 글씨에서는 메뉴 1열, 상단 요소 세로 배치
- 장바구니·버튼이 화면 아래에 가려지지 않도록 SafeArea와 하단 여백 적용
- 가격만으로 선택하지 않도록 메뉴명과 아이콘을 함께 표시
- 따라 해보기 강조는 색만 사용하지 않고 안내 문구도 함께 제공
- `실패`, `틀렸습니다`, `오답` 표현을 사용하지 않음

## 10. V1 호환 및 전환 전략

1. 기존 V1 라우트와 화면을 유지한 채 V2 모델·위젯·라우트를 추가한다.
2. V2는 기존 `CafeLearningMode`를 입력으로 받아 모드별 UX를 구분한다.
3. 완료 시 기존 `completeCafeLearning()`만 호출한다.
4. 기존 SharedPreferences 키와 최근 기록 형식을 변경하지 않는다.
5. V1과 V2의 완료 결과가 동일한 포인트·배지·횟수로 기록되는지 계약 테스트를 작성한다.
6. V2 전체 흐름과 접근성 테스트가 통과한 뒤 카페 시작 화면의 진입 경로만 V2로 전환한다.
7. 한 릴리스 동안 V1 라우트를 유지해 오래된 딥링크나 진행 중 경로가 깨지지 않게 한다.
8. 안정화 후에도 기존 저장 키와 완료 API는 유지하고 사용하지 않는 V1 화면만 별도 작업으로 정리한다.

## 11. 구현 권장 순서

### 1단계: 데이터와 상태

- 가상 메뉴 데이터와 enum 정의
- `CafeOrderSession`, `CafeOrderProvider` 구현
- 선택·이전·수량·초기화 단위 테스트
- 혼자 해보기 미션 모델 확장 및 단계별 판정 테스트

### 2단계: 읽기 전용 메뉴판

- `CafeKioskShell`, 상단, 카테고리, 메뉴 카드 구현
- 320dp·보통/크게/아주 크게·편안한/선명한 화면 테스트
- 아직 V1 진입점은 변경하지 않음

### 3단계: 옵션 흐름

- 온도, 크기, 매장/포장 화면 연결
- 따라 해보기 강조와 혼자 해보기 비강조·힌트 적용
- 이전·다시 하기·직접 경로 진입 보호 테스트

### 4단계: 장바구니와 연습 결제

- 장바구니, 수량, 가상 가격 합계 구현
- 연습용 결제 확인 화면 구현
- 실제 입력·전송 기능이 없음을 테스트와 문구로 보장

### 5단계: 기존 보상 연동

- 기존 완료 화면과 `completeCafeLearning()` 연결
- 재진입·반복 클릭·Provider 재생성 중복 보상 테스트 재사용
- 최근 기록과 배지 회귀 테스트

### 6단계: 진입점 전환

- 카페 시작·미션 화면에서 V2 메뉴 화면으로 이동
- 홈·연습·미션 탭부터 완료·홈 복귀까지 통합 테스트
- V1 라우트는 호환 경로로 유지

## 12. 테스트 계획

- 메뉴 카테고리별 필터와 가격 표시
- 메뉴 선택 후 옵션 화면의 요약값
- 옵션 선택·이전 후 상태 유지
- 수량 변경과 가상 합계 계산
- 비어 있는 장바구니 보호
- 혼자 해보기 정답·다른 선택·힌트
- 따라 해보기 추천 표시가 혼자 해보기에 노출되지 않음

## 14. 최종 구현 결과

### 최종 화면 흐름

카페 시작 화면에서 기존 따라 해보기 또는 혼자 해보기를 선택한 뒤 아래 순서로 진행한다.

1. 카테고리와 메뉴 선택
2. 온도 선택
3. 크기 선택
4. 매장 또는 포장 선택
5. 장바구니 확인과 수량 조절
6. 연습용 포인트 적립 방식 선택
7. 연습용 결제 수단 선택
8. 영수증형 완료 화면과 기존 보상 처리

### 키오스크형 레이아웃 원칙

- 배경은 아이보리 #FAF9F4, 주요 글자와 아이콘은 진한 초록 #23413C를 사용한다.
- 상단에는 낮은 앱 바, 단계 표시, 장바구니와 수량 배지만 둔다.
- 선택 중인 메뉴와 옵션은 큰 카드 대신 상단의 한 줄 요약으로 표시한다.
- 각 단계의 핵심 진행 버튼은 SafeArea 안의 하단 고정 영역에 하나만 강조한다.
- 검은 Snackbar, Toast, 화면을 가리는 힌트 팝업을 사용하지 않는다.
- 혼자 해보기의 힌트와 다른 선택 안내는 질문 아래의 세이지색 인라인 영역에 표시한다.

### 화면별 최종 구성

- **메뉴판:** 가로 스크롤되는 5개 카테고리와 2열 메뉴 그리드를 사용한다. 메뉴 타일은 아이콘, 한 줄 메뉴명, 가상 가격으로 구성한다.
- **옵션:** 온도, 크기, 매장·포장을 한 화면에 하나씩 제시한다. 두 선택지는 동일한 크기의 가로 버튼이며 선택된 항목만 세이지 배경과 초록 테두리를 사용한다.
- **장바구니:** 메뉴명과 옵션, 삭제, 빼기·수량·더하기, 가상 가격을 구분선 기반 목록으로 표시한다. 총 가상 금액과 주문 확인 버튼은 하단에 고정한다.
- **포인트 적립:** 전화번호, 카카오톡, 적립하지 않기를 아이콘·이름·선택 표시가 있는 목록으로 제공한다.
- **결제:** 신용카드, 카카오페이, 삼성페이, 현금을 일반 아이콘과 텍스트 목록으로 제공한다.
- **완료:** 메뉴와 옵션, 적립 방식, 결제 방법, 총 가상 금액을 영수증 순서로 표시하고 포인트·배지는 별도 세이지 안내 영역으로 구분한다.

### 연습 기능 제한

전화번호 입력, 메신저 연결, 카드·QR·현금 처리, 주문 전송은 구현하지 않는다. 모든 가격과 결제 수단은 키오스크 사용 순서를 익히기 위한 앱 내부의 가상 정보이며 실제 적립이나 결제가 발생하지 않는다.

### 구현 상태와 공통 위젯

- CafeOrderProvider가 메뉴, 카테고리, 온도, 크기, 매장·포장, 수량, 적립 방식, 결제 수단을 메모리에서 관리한다.
- LearningProgressProvider.completeCafeLearning()과 기존 SharedPreferences 키가 포인트, 횟수, 배지, 최근 기록 및 중복 지급 방지를 담당한다.
- CafeKioskScaffold가 상단 바, 주문 요약 줄, 본문, 하단 고정 동작을 통일한다.
- CafeCategoryTabs, CafeMenuCard, CafeOptionCard, CafeSelectionRow, CafeCartItemCard, CafePracticeNotice를 V2 화면에서 재사용한다.
- 기존 V1 카페 화면과 라우트는 삭제하지 않고 호환 경로로 유지한다.

### 최종 검증

- 320dp와 아주 큰 글씨에서 메뉴 2열, 옵션, 장바구니, 적립, 결제 화면의 렌더링 예외가 없는지 위젯 테스트로 확인한다.
- 장바구니에 메뉴 3개를 담은 상태에서도 목록 스크롤과 하단 합계 영역이 정상인지 확인한다.
- 따라 해보기와 혼자 해보기의 판정, 인라인 힌트, 포인트, 첫 배지, 최근 기록 및 중복 보상 방지 테스트를 유지한다.
- Small Phone Android 에뮬레이터에서 메뉴판부터 영수증형 완료 화면까지 직접 진행하고 RenderFlex 오버플로우 로그가 없음을 확인한다.
