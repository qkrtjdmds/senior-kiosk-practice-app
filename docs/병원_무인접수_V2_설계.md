# 병원 무인 접수 V2 설계

## 목표와 범위

병원 접수 V2는 실제 병원 시스템과 연결되지 않는 가상 무인 접수 연습이다. 실제 이름, 주민등록번호, 전화번호, 진료 정보는 입력·저장·전송하지 않는다. 기존 병원 V1 소스는 유지하고 기존 병원 라우트에서 V2 화면을 제공한다.

## 화면 흐름

1. 시작 화면에서 `따라 해보기` 또는 `혼자 해보기` 선택
2. 접수 시작과 도움 요청 안내
3. `진료 접수` 업무 선택
4. 처음 방문 또는 이전 방문 선택
5. 연습용 환자 `김한걸음`, 생년월일 `1958년 4월 12일` 확인
6. 예약 여부 선택
7. 내과·정형외과·이비인후과 중 진료과 선택
8. 방문 이유 선택
9. 접수 내용 확인
10. 연습용 접수 번호와 완료 보상 표시

따라 해보기는 고정된 권장 선택을 부드럽게 강조한다. 혼자 해보기는 정답을 강조하지 않으며 미션과 다른 선택에서 현재 단계를 유지하고 인라인 안내와 반복 가능한 힌트를 제공한다.

## 혼자 해보기 미션

- 처음 방문 · 예약 없음 · 내과 · 배가 불편해요
- 이전 방문 · 예약 있음 · 정형외과 · 무릎이 아파요
- 이전 방문 · 예약 없음 · 이비인후과 · 귀·코·목 관련 불편함

완료 횟수에 따라 세 미션을 순환해 한 세션 동안 같은 목표를 유지한다. 기존 오늘의 미션 콘텐츠 식별자와 완료 판정은 변경하지 않는다.

## 상태와 개인정보 보호

`HospitalReceptionProvider`는 현재 단계, 모드, 선택 결과, 인라인 안내를 메모리에서만 관리한다. 환자 확인 숫자는 완료·이탈·재시작 시 삭제하며 SharedPreferences에 저장하지 않는다. 앞 단계로 돌아가면 뒤 단계에서 고른 값도 정리한다.

완료 보상은 기존 `LearningProgressProvider.completeHospitalLearning()`과 `completeHospitalSoloLearning()`을 그대로 사용한다. 따라서 따라 해보기 10점, 혼자 해보기 20점, 첫 완료 배지, 최근 기록, 세션 중복 지급 방지 키가 V1과 호환된다. 미션 탭에서 시작한 완료는 기존 `DailyMissionProvider`로 추가 보상을 판정한다.

## UI 원칙

- 아이보리 배경과 진한 초록, 세이지 강조색
- 병원 안내에는 연한 파랑, 긴급 안내에는 차분한 주황 사용
- 최소 높이를 확보한 큰 선택 행과 하단 핵심 버튼
- 작은 화면과 큰 글씨에서 줄바꿈 가능한 텍스트와 세로 스크롤
- 검은 Snackbar 대신 화면 안 인라인 안내
- 실제 진단이나 위급 상황 판단을 하지 않고 직원 도움 요청을 안내

## Android 에뮬레이터 최종 검증

- 환경: `Small_Phone`, Android 15(API 35), 기본 360dp 및 320dp 폭
- 설치: 기존 앱 데이터를 유지하는 `adb install -r` 사용
- 따라 해보기: 진료 접수 → 이전 방문 → 연습용 환자 확인 → 예약 있음 → 내과 → 감기 증상 → 접수 확인 → 완료까지 직접 진행
- 확인 결과: 연습용 대기 번호, 10점 보상, 실제 접수가 아니라는 안내가 정상 표시됨
- 업무 선택: 진료 접수·예약 확인·진료비 수납·서류 발급 네 업무 모두 사용 가능
- 환자 확인: 한 자리 지우기와 전체 지우기 제공, 입력값 마스킹, 잘못된 값과 부족한 자릿수 진행 차단
- 개인정보: 연습용 생년월일·이름·방문 이유가 SharedPreferences와 logcat에 남지 않음을 검사
- 진료과: 내과·정형외과·이비인후과·안과·피부과·신경과와 쉬운 설명 제공
- 방문 이유: 선택한 진료과에 맞는 목록과 `기타·잘 모르겠어요` 제공, 자유 입력은 받지 않음
- 직원 도움: 시작·환자 확인·진료과·접수 확인에서 실제 호출이 아닌 인라인 안내 제공
- 응급 안내: 가까운 직원 또는 119에 도움을 요청하도록 차분한 주의 영역으로 표시
- 상태 정리: 이전 단계 변경 시 이후 선택 제거, 완료·이탈·재시작 시 환자 확인 숫자 제거
- 혼자 해보기: 세 시나리오 데이터, 오선택 차단, 힌트, 20점·첫 배지를 자동 테스트로 검증
- 오늘의 미션: 기존 병원 콘텐츠 ID, 중도 이탈 취소, 완료 시 추가 10점 및 중복 방지를 기존 DailyMissionProvider 테스트로 검증
- 발견 및 수정: 준비 중 업무 부족, 업무명 누락, 3개뿐인 진료과, 전체 지우기 부재, 입력 숫자 노출, 접수 확인의 방문 행 중복, 완료 요약의 방문 정보 누락을 수정
- 회귀 검사: 전체 Flutter 테스트와 Android 디버그 APK 빌드 통과

### 남은 제한 사항

이 기능은 실제 병원·예약·건강보험 시스템과 연결되지 않으며 의료 진단이나 치료 안내를 제공하지 않는다. 실제 기기별 제조사 글꼴과 접근성 서비스 조합은 별도 사용자 사용성 테스트가 필요하다.
## 가상 환자 확인 키패드 개선

실제 Small Phone과 큰 글씨에서 삭제 문구가 여러 줄로 나뉘고 도움 버튼이 입력보다 먼저 강조되는 문제를 확인했다. 화면 순서를 짧은 안내, 연습 정보, 마스킹 입력 자리, 3×4 키패드, 환자 확인, 직원 도움 순서로 정리했다.

- 안내를 `화면에 적힌 연습용 생년월일 8자리를 입력해 보세요.`로 단순화
- 연습 정보 카드에 날짜와 실제 정보 입력 금지 안내를 함께 표시
- 입력 숫자는 표시하지 않고 8개의 `●/○` 자리로 상태만 표시
- `8자리 중 N자리 입력됨` Semantics 제공
- 삭제 키를 세이지 배경의 `backspace_outlined + 한 글자`, `delete_outline + 전체`로 구성
- 아주 큰 글씨에서는 짧은 라벨도 숨기고 아이콘과 접근성 설명을 유지
- 직원 도움 버튼을 확인 버튼 아래의 외곽선 보조 동작으로 이동
- 도움 요청 후 단계와 입력값은 유지하고 실제 호출이 아니라는 인라인 안내 표시
- 8자리 전에는 읽기 가능한 대비의 비활성 확인 버튼, 8자리부터 진한 초록 활성 버튼 사용
- 320dp·아주 큰 글씨 위젯 테스트에서 3열 정렬, 삭제 키, 버튼 상태와 RenderFlex overflow 부재 확인
- 환자 확인 숫자는 SharedPreferences와 로그에 저장하지 않으며 이전·이탈·완료·재시작 시 제거
## 예약 확인 연습

병원 V2 업무 선택에서 `진료 접수`, `예약 확인`, `진료비 수납`, `서류 발급` 네 업무를 모두 사용할 수 있다. 각 업무는 독립 Provider와 완료 기록을 사용한다.

### 전체 흐름

1. 업무 선택
2. 공통 가상 환자 확인
3. 가상 예약 선택
4. 예약 상세 확인
5. 예약 확인 완료와 실제 병원 이용 안내

예약 확인 전용 화면은 `1 / 5`부터 `5 / 5`까지 표시하며 진료 접수의 8단계 진행 상태와 분리한다. 시스템 뒤로가기와 상단 뒤로가기는 같은 상태 정리 함수를 사용한다.

### 가상 예약 데이터

- 오늘 · 오전 10:30 · 내과 · 2진료실 · 정기 진료 · 예약됨
- 내일 · 오후 2:00 · 정형외과 · 1진료실 · 무릎 진료 · 예약됨
- 다음 주 화요일 · 오전 11:00 · 이비인후과 · 3진료실 · 귀·코·목 진료 · 예약됨

모든 예약에는 안정적인 연습용 ID와 `isPracticeData` 표시가 있으며 실제 병원명이나 의사 이름은 포함하지 않는다.

### 따라 해보기와 혼자 해보기

따라 해보기는 오늘 오전 10시 30분 내과 2진료실 예약을 목표로 사용한다. 다른 항목을 고르면 예약 목록에 머물며 날짜와 진료과를 다시 확인하라는 인라인 안내를 표시한다.

혼자 해보기는 완료 횟수에 따라 위 세 예약을 순환한다. 시작 화면에서 전체 목표를 한 번 보여주고 목록에서는 정답을 강조하지 않는다. 사용자가 `힌트 보기`를 눌렀을 때만 날짜·시간·진료과·진료실을 안내한다. 예약 확인 시나리오 ID는 기존 진료 접수 시나리오 ID와 별도다.

### 환자 확인 재사용과 개인정보 보호

진료 접수, 예약 확인, 진료비 수납, 서류 발급 네 업무는 `HospitalPatientVerification` 공통 위젯을 사용한다. 연습용 값 `19580412`만 다음 단계로 진행하며 한 글자·전체 삭제, 마스킹 자리, 직원 도움 안내, 320dp 큰 글씨 반응형 동작을 공유한다. 입력 원문은 Provider 메모리에만 잠시 존재하고 예약 목록 진입, 이전 이동, 완료, 재시작 및 이탈 시 제거한다. SharedPreferences와 로그에는 저장하지 않는다.

### 예약 목록·상세·완료

예약 목록은 구분선 기반의 낮은 행으로 날짜·시간, 진료과, 진료실, 방문 목적, 예약 상태를 표시한다. 예약 상세에서는 가상 환자 확인 완료와 실제 예약에 연결되지 않는다는 안내를 함께 보여준다. 완료 화면은 예약 요약, 실제 병원 이용 안내, 다시 연습, 업무 선택, 홈 이동을 제공한다. 환자 확인·목록·상세 화면의 직원 도움은 실제 호출 없이 현재 상태를 유지한 인라인 안내만 표시한다.

### 업무별 보상과 오늘의 미션

예약 확인 따라 해보기는 10점, 혼자 해보기는 20점과 별도 완료 횟수 및 `병원 예약 확인` 최근 기록을 저장한다. 진료 접수와 다른 SharedPreferences 세션 키를 사용해 완료 화면 재진입과 빠른 연속 요청을 차단한다. 연습 기록 초기화에는 예약 확인 키도 포함되지만 글씨 크기와 화면 대비 설정은 유지된다.

기존 병원 오늘의 랜덤 미션 ID와 판정은 변경하지 않았다. 예약 확인 완료는 기존 진료 접수 일일 미션을 완료시키거나 추가 10점을 지급하지 않는다. 향후 업무별 일일 미션을 추가할 수 있도록 예약 시나리오 ID를 독립적으로 관리한다.

### 반응형·접근성 및 검증

- 모든 주요 버튼 최소 높이 56dp
- 예약 항목 전체 터치 및 의미 있는 Semantics
- 상태를 체크 아이콘과 한국어 문구로 함께 표시
- 320dp와 아주 큰 글씨에서 스크롤, Flexible, 줄바꿈으로 오버플로우 방지
- 마지막 예약과 완료 버튼에 충분한 하단 여백 제공
- Provider 단위 테스트: 3개 예약, 생년월일 차단, 시나리오 순환, 오선택 유지, 상태 초기화
- 위젯 테스트: 예약 확인 진입, 5단계 표시, 목록 3개, 오선택, 상세, 완료, 10점
- 보상 테스트: 따라 10점, 혼자 20점, 동시 요청 중복 방지, 최근 기록, 기록 초기화 후 설정 유지

실제 병원 API, 실제 예약번호, 실제 개인정보, 예약 변경·취소 및 직원 호출 기능은 구현하지 않는다.

## 진료비 수납 연습

병원 V2 업무 선택에서 진료비 수납과 서류 발급을 모두 사용할 수 있다. 모든 금액·결제·출력 과정은 앱 내부의 가상 연습이며 실제 병원·카드·계좌·결제·문서 서비스와 연결되지 않는다.

### 전체 흐름

1. 업무 선택
2. 공통 가상 환자 확인
3. 가상 진료비 선택
4. 진료비 상세 확인
5. 결제 수단 선택
6. 결제 순서와 영수증 선택 연습
7. 완료 및 실제 병원 이용 안내

### 가상 진료비

- 오늘 · 내과 · 진찰료 · 18,500원 · 미납
- 어제 · 정형외과 · 진찰료 및 가상 검사비 · 32,000원 · 미납
- 지난주 · 이비인후과 · 진찰료 · 12,700원 · 납부 완료

금액은 정수 원 단위로 관리하고 표시할 때 천 단위 쉼표를 붙인다. 납부 완료 항목은 상태 아이콘과 문구를 함께 표시하며 선택해도 현재 목록에 머문다.

### 결제 방법과 영수증

카드 연습은 카드 넣기, 금액 확인, 가상 승인, 카드 챙기기를 순서대로 진행한다. 카드 챙기기 전에는 완료할 수 없다. 간편결제는 휴대전화 준비, 가상 인식 위치 확인, 금액 확인 순서이며 QR·바코드·카메라·결제 앱 연동은 없다. 현금은 키오스크 결제 완료라고 표현하지 않고 원무창구 위치와 직원 문의 방법을 확인하는 흐름으로 처리한다.

카드와 간편결제 뒤에는 영수증 받기 또는 받지 않기를 선택한다. 받기를 고르면 완료 화면에 `실제 영수증이 아닙니다`가 표시된 가상 영수증을 보여준다. PDF와 프린터 기능은 제공하지 않는다.

### 따라 해보기와 혼자 해보기

따라 해보기 목표는 오늘 내과 18,500원, 카드, 영수증 받기다. 혼자 해보기는 다음 세 시나리오를 완료 횟수에 따라 순환한다.

- 오늘 내과 18,500원 · 카드 · 영수증 받기
- 어제 정형외과 32,000원 · 간편결제 · 영수증 받지 않기
- 오늘 내과 18,500원 · 현금 · 원무창구 안내 확인

목표와 다른 내역·결제 방법·영수증을 고르면 현재 단계에 머물며 긍정적인 인라인 안내를 표시한다. 정답은 목록에서 강조하지 않으며 힌트는 사용자가 요청할 때만 제공한다.

### 보상·상태·개인정보

따라 해보기는 10점, 혼자 해보기는 20점과 업무별 완료 횟수, `병원 진료비 수납` 최근 기록을 저장한다. 진료 접수·예약 확인과 별도 세션 키를 사용해 재진입과 빠른 연속 요청을 막는다. 기존 병원 일일 미션은 계속 진료 접수 혼자 해보기에만 연결되며 수납 완료는 일일 미션을 완료시키지 않는다.

환자 확인 숫자, 카드번호, 비밀번호, 계좌, 휴대전화 결제 정보는 저장하거나 입력받지 않는다. 내역 변경 시 결제 상태를, 결제 방법으로 뒤로 이동할 때 진행 순서와 영수증 선택을 제거한다. 업무 선택·홈·재시작에서는 모든 수납 임시 상태를 초기화한다.

### 반응형·테스트

- 공통 `HospitalPatientVerification` 키패드 재사용
- 7단계 전용 진행 표시와 `PopScope` 뒤로가기
- 목록·상세·결제·영수증 화면의 세로 스크롤과 최소 56dp 버튼
- 상태를 아이콘과 문구로 함께 표현하고 항목별 Semantics 제공
- 320dp 위젯 테스트에서 목록, 납부 완료 차단, 카드 순서, 영수증, 완료 화면 검증
- Provider 테스트에서 3개 청구, 세 시나리오, 결제 순서, 카드 회수 전 차단, 상태 초기화 검증
- 보상 테스트에서 10점·20점, 업무별 기록, 빠른 중복 요청 차단 검증

실제 결제 SDK, NFC, 카드리더기, QR·바코드, 실제 진료비 API와 실제 영수증 출력은 구현하지 않는다.

## 서류 발급 연습 최종 구현

병원 V2 업무 선택의 서류 발급을 활성화했다. 흐름은 업무 선택, 공통 가상 환자 확인, 서류 선택, 제출 용도, 발급 부수, 신청 확인, 가상 결제와 출력, 서류 챙기기 및 완료의 8단계다.

### 연습용 서류와 수수료

- 통원확인서 3,000원
- 진료확인서 3,000원
- 진료비 납입확인서 1,000원
- 처방전 사본 500원
- 진단서는 의사 확인 또는 원무창구 방문이 필요할 수 있다는 정보만 제공하며 키오스크 발급을 진행하지 않는다.

모든 서류와 금액은 연습용 가상 데이터다. 발급 부수는 1~3부이며 총 가상 수수료는 1부 수수료와 부수의 곱으로 계산한다. 실제 문서, PDF, 프린터, 병원 API와 연결하지 않는다.

### 따라 해보기와 혼자 해보기

따라 해보기 목표는 통원확인서, 보험회사 제출, 1부, 카드 결제다. 혼자 해보기는 다음 세 목표를 완료 횟수에 따라 순환한다.

- 통원확인서 · 보험회사 제출 · 1부 · 카드
- 진료비 납입확인서 · 회사 제출 · 2부 · 간편결제
- 처방전 사본 · 개인 보관 · 1부 · 카드

목표와 다른 선택은 현재 단계에 머물고 긍정적인 인라인 안내를 표시한다. 힌트는 요청한 경우에만 현재 단계에 필요한 선택을 보여준다.

### 결제·출력·보상

카드는 카드 넣기, 금액 확인, 가상 결제, 카드 챙기기 순서로 진행한다. 간편결제는 휴대전화 준비, 가상 인식 위치와 금액 확인, 가상 결제 순서다. 현금은 실제 병원의 원무창구 문의 안내만 제공한다. 결제 뒤 출력이 끝났어요, 서류를 챙겼어요를 차례로 눌러야 완료할 수 있다.

HospitalDocumentProvider는 다른 병원 업무와 독립적으로 임시 상태를 관리한다. 환자 확인 숫자와 선택 내용은 저장하지 않는다. LearningProgressProvider에는 따라 해보기 10점, 혼자 해보기 20점, 업무별 완료 횟수, 세션 중복 방지 키, 병원 서류 발급 최근 기록만 저장한다. 기존 오늘의 랜덤 미션은 진료 접수 혼자 해보기에만 연결하며 서류 발급 완료로 추가 미션 보상을 지급하지 않는다.

공통 HospitalPatientVerification, HospitalKioskScaffold, 선택·안내 위젯을 재사용한다. 320dp와 큰 글씨에서 목록과 확인 행이 줄바꿈되고 모든 주요 버튼은 최소 56dp 터치 영역을 유지한다. 병원 V2의 네 업무는 모두 사용 가능하다.
