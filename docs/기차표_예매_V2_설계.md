# 기차표 예매 V2 설계 및 구현

## 목적과 V1 차이

어르신이 편도·왕복 구분부터 모바일 승차권 확인까지 일반적인 기차표 예매 과정을 안전한 가상 데이터로 연습한다. V1의 5단계 문자열 선택을 역 검색, 한국 날짜 달력, 시간대, 승객, 가상 열차, 객실·운임, 좌석도, 결제와 승차권 흐름으로 확장했다. 기존 V1 소스와 저장 키는 유지한다.

## 전체 흐름

모드 선택 → 편도·왕복 → 출발·도착역 → 날짜 → 시간대 → 승객 → 조건 확인 → 열차 조회 → 객실 → 좌석 → 예매 확인 → 가상 결제 → 모바일 승차권 순서다.

## 역·날짜·승객

서울, 용산, 광명, 수원, 천안아산, 대전, 동대구, 부산, 광주송정, 목포, 전주, 여수엑스포, 강릉, 청량리를 앱 내부 데이터로 제공한다. 이름·일부 글자·등록 초성으로 검색하며 GPS는 사용하지 않는다. 날짜는 주입 가능한 clock의 한국 날짜(UTC+9)를 기준으로 오늘부터 30일까지다. 왕복의 오는 날짜는 가는 날짜보다 빠를 수 없다. 성인·어린이·경로는 합계 1~4명이며 개인정보와 실제 할인 자격은 확인하지 않는다.

## 가상 열차·객실·운임

`한걸음 고속`, `한걸음 일반`과 H101·H205·G307 등 가상 열차를 사용한다. 구간과 시간대에 맞춘 것처럼 앱 내부에서 생성하고 출발 시각순으로 정렬한다. 일반실·우등실 운임은 성인 100%, 어린이 50%, 경로 70%의 연습용 비율로 정수 원 단위 계산하며 왕복은 합산한다.

## 좌석도와 확인

5행, 2열+통로+2열의 20석을 제공한다. A·D는 창가, B·C는 통로다. 선택·예약 상태를 문구, 테두리와 Semantics로 구분하고 승객 수만큼 골라야 진행한다. 예매 확인에는 구간, 날짜, 열차, 객실, 좌석, 승객과 가상 운임을 표시한다.

## 결제와 모바일 승차권

카드·간편결제 연습만 제공한다. 카드번호·비밀번호·실제 QR·결제 SDK는 사용하지 않는다. 모바일 승차권의 QR 모양은 인식되지 않는 장식이며 `연습용`과 실제 탑승 불가 안내를 표시한다.

## 시나리오

- 따라 해보기: 편도, 서울→부산, 내일 오전, 성인 1명, H101, 일반실, 창가 1A, 카드
- 혼자 A: 기본 편도 예매
- 혼자 B: 용산→광주송정, 이틀 뒤 낮, 성인 1명·경로 1명, 우등실, 간편결제
- 혼자 C: 서울↔강릉 왕복, 사흘 뒤 오전 출발·나흘 뒤 저녁 귀환, 성인 1명, 일반실, 카드

혼자 해보기는 정답을 강조하지 않고 요청 시 현재 단계 힌트만 제공한다. 다른 선택은 긍정적인 인라인 안내와 함께 현재 단계에 머문다.

## 미션·기록·중복 방지

기존 `train_solo_complete` 미션 ID를 유지한다. 미션 탭에서 시작한 활성 미션만 완료 시 추가 10점을 받는다. 기존 따라 해보기 10점, 혼자 해보기 20점, 첫 배지, 완료 횟수, 최근 기록과 SharedPreferences 세션 중복 지급 방지를 그대로 사용한다.

## 상태와 접근성

편도·왕복, 역, 날짜, 시간대, 승객, 열차, 객실, 좌석 변경 시 뒤 단계의 오래된 결과를 정리한다. 320dp와 아주 큰 글씨에서 세로 스크롤, SafeArea, 56dp 이상 버튼을 사용하며 상태는 색상 외 아이콘·테두리·문구로 함께 전달한다. 검은 Snackbar와 Toast는 사용하지 않는다.

## 구현 파일과 검증

- `train_booking_models.dart`: 역·열차·좌석·시나리오 모델
- `train_booking_provider.dart`: 상태, 검증, 조회, 운임과 초기화
- `train_booking_widgets.dart`: 공통 화면·선택·인라인 안내
- `train_v2_pages.dart`: 전체 화면 흐름

자동 테스트는 날짜 주입, 왕복 정리, 검색, 승객 제한, 시간표, 매진, 운임, 좌석과 카드 회수를 검증한다. 실제 철도 API·예약·결제·로그인·GPS는 연결하지 않는다. 다음 V2 후보는 무인민원발급기 연습이다.

## 최종 에뮬레이터 검증

Android 15(API 35) `Small_Phone` 에뮬레이터에 기존 데이터를 유지한 채 디버그 APK를 덮어 설치했다. 따라 해보기의 서울→부산 편도 시나리오를 모드 선택부터 날짜, 오전 시간대, 성인 1명, H101, 일반실, 1A, 카드 회수와 연습용 승차권까지 완료했다. 혼자 해보기에서는 목표 카드, 정답 비강조, 다른 선택 시 단계 유지, 긍정적인 인라인 안내와 요청 시에만 나타나는 힌트를 확인했다.

360dp와 320dp 폭의 아주 큰 글씨에서 모드 선택, 편도·왕복, 역 목록, 달력, 시간대, 승객, 열차 목록, 객실, 5x4 좌석도, 예매 확인, 결제와 승차권을 세로 스크롤 및 고정 하단 버튼으로 사용할 수 있음을 확인했다. 검은 Snackbar·Toast, 가로 스크롤, 시스템 영역 및 하단 버튼 겹침은 사용하지 않는다.

## 최종 수정 사항

- 왕복에서 돌아오는 열차나 객실을 선택할 때 가는 편 좌석이 지워지던 상태 전환을 수정했다.
- 왕복 좌석 단계는 가는 편 좌석 개수가 아니라 명시적인 귀환 여정 상태를 사용한다.
- Android 시스템 뒤로가기를 상단 뒤로가기와 같은 콜백에 연결했다.
- 결제 수단 선택 전에 예매 합계와 같은 가상 결제 금액을 표시한다.
- 왕복 연습용 승차권에 오는 편 열차·시각·객실·좌석과 결제 방법을 함께 표시한다.
- 혼자 해보기 초기화를 라우트 build 밖의 첫 프레임 이후로 옮겨 Provider 알림 생명주기 오류를 제거했다.
- 왕복 귀환 열차·객실 선택 뒤 가는 편 좌석이 보존되는 회귀 테스트를 추가했다.

## 검증 범위와 제한

Provider 테스트로 한국 날짜 범위, 왕복 상태 정리, 같은 역 차단과 검색, 승객 1~4명 제한, 매진 및 잔여 좌석, 성인·어린이·경로 운임, 좌석 수 제한, 카드 회수와 왕복 귀환 좌석 보존을 검증한다. 앱 전체 테스트는 기존 콘텐츠, 설정, 기록 초기화와 보상 중복 방지를 함께 검사한다.

모든 역·열차·좌석·운임·결제·승차권은 앱 내부 가상 데이터다. 실제 철도 시간표, 예약, 결제, 카드 정보, 회원정보, GPS 및 인식 가능한 QR·바코드는 제공하지 않는다. 다음 예정 작업은 `무인민원발급기 V2`다.
## 최종 디자인 방향

정보의 순서와 조작 흐름은 일반적인 철도 예매 앱처럼 `예매 조건 → 열차 시간표 → 객실·객차 → 좌석 → 예매 확인 → 결제 연습 → 연습용 승차권`으로 구성한다. 특정 서비스의 로고, 고유 색상이나 화면을 복제하지 않으며 한걸음 디지털의 아이보리 `#FAF9F4`, 진한 초록 `#23413C`, 연한 세이지 `#E5EDE5`를 그대로 사용한다.

- 편도·왕복은 짧은 구간 선택으로 표시하고 선택 상태를 초록 테두리와 세이지 배경으로 구분한다.
- 열차 조회는 출발·도착 시각을 가장 먼저 보여주고 열차명·번호·소요 시간, 일반실·우등실 운임, 잔여 좌석과 매진 여부를 구분선 기반 시간표 행으로 정리한다.
- 좌석 화면은 1~4호차를 먼저 고른 뒤 A·D 창가, B·C 통로가 구분된 2+2 좌석도를 사용한다. 객차 변경 시 해당 여정의 좌석을 다시 고르도록 정리한다.
- 예매 확인과 연습용 승차권은 선택한 객실·객차·좌석과 가상 금액을 동일하게 표시한다.
- 320dp 또는 아주 큰 글씨에서는 두 항목 선택은 세로로, 네 객차 선택은 2×2로 배치한다. 하단 핵심 버튼은 SafeArea 안에 고정한다.
