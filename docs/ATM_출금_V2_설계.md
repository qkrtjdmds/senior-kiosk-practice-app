# ATM 출금 V2 설계 및 구현

## 목적

ATM 출금 V2는 특정 은행 화면을 복제하지 않고, 여러 ATM에서 공통으로 만나는 출금 순서와 카드·현금 회수 습관을 연습하는 가상 화면이다. 실제 카드, 계좌번호, PIN, 금융 API 또는 서버는 사용하지 않는다.

## V1 호환

- 기존 진입 경로 `/atm`, 미션 경로 `/atm/mission`, 미션 ID `atm_solo_complete`를 유지한다.
- `LearningProgressProvider`의 기존 ATM 완료 횟수, 포인트, 첫 완료 배지, 최근 기록 키와 보상 메서드를 그대로 사용한다.
- 기존 ATM V1 소스는 삭제하지 않았고 다른 학습 콘텐츠는 수정하지 않았다.

## 화면 흐름

1. 따라 해보기 또는 혼자 해보기 선택
2. ATM 업무 목록에서 현금 출금 선택
3. 거래 종류 확인
4. 연습용 카드 넣기
5. 연습용 PIN 1234 입력
6. 가상 계좌 선택
7. 빠른 금액 또는 직접 금액 선택
8. 금액·수수료·차감 예정 금액 확인
9. 가상 출금 진행
10. 카드 먼저 챙기기
11. 현금 챙기기
12. 명세표 선택
13. 연습 완료 및 기존 보상 처리

## 가상 데이터 정책

- 계좌는 `연습용 계좌 1`, `연습용 계좌 2`만 사용하며 실제 계좌번호를 표시하지 않는다.
- 가상 잔액은 각각 850,000원과 320,000원이다.
- 금액은 1만 원 단위, 최소 1만 원, 최대 30만 원으로 제한한다.
- 일부 혼자 해보기 시나리오만 가상 수수료 1,000원을 사용한다. 출금 금액과 수수료는 별도 표시하고 합계가 가상 잔액을 넘지 않도록 검증한다.

## PIN 보호

- 연습 PIN은 1234이며 `AtmWithdrawalProvider` 메모리에만 잠시 보관한다.
- 화면에는 입력 자릿수만 점으로 표시하고 로그나 SharedPreferences에 저장하지 않는다.
- 확인, 초기화, 완료, 앱 백그라운드 전환 시 즉시 지운다.

## 따라 해보기와 혼자 해보기

- 따라 해보기는 입출금 계좌, 50,000원, 수수료 0원, 명세표 받지 않기를 안내한다.
- 혼자 해보기는 기존 ATM 혼자 완료 횟수를 기준으로 3개 미션을 순환한다.
  1. 입출금 계좌 · 30,000원 · 수수료 0원 · 명세표 받지 않기
  2. 생활비 계좌 · 100,000원 · 수수료 1,000원 · 명세표 받기
  3. 입출금 계좌 · 200,000원 · 수수료 0원 · 명세표 받기
- 혼자 해보기는 정답을 미리 강조하지 않고 인라인 힌트만 제공한다.

## 보상과 일일 미션

- 따라 해보기는 기존 `completeAtmLearning()`으로 10점을 지급한다.
- 혼자 해보기는 기존 `completeAtmSoloLearning()`으로 20점과 첫 완료 배지를 처리한다.
- 실제 혼자 완료 횟수가 증가한 경우에만 `DailyMissionProvider.completeActiveMission(MissionContentType.atm)`을 호출한다.
- 카드, PIN, 계좌, 금액, 거래 확인, 카드 회수, 현금 회수, 명세표 선택이 모두 끝나야 완료 화면에서 보상을 요청한다.
- 기존 세션 지급 플래그가 재진입과 빠른 중복 요청을 차단한다.

## 상태 초기화

- 새 연습은 모든 ATM 임시 상태를 초기화한다.
- 카드 단계 이전 이동은 PIN 이후 상태를 지운다.
- 계좌 변경은 금액 이후 상태를, 금액 변경은 확인 이후 상태를 지운다.
- 완료·이탈·재시작에서 PIN은 항상 지운다.

## 접근성

- 주요 버튼은 56dp 이상, 선택 행은 70dp 이상이다.
- 320dp와 큰 글씨에서는 금액 그리드가 한 열로 바뀌고 삭제 키의 문구 공간이 부족하면 아이콘만 남긴다.
- 삭제 키는 아이콘 전용 상태에서도 스크린 리더용 의미를 유지한다.
- 오류와 힌트는 검은 팝업 대신 화면 안의 베이지·세이지 안내 영역으로 표시한다.

## 제한

실제 카드 인식, PIN 저장, 계좌 조회, 출금, 명세표 출력, 금융기관 연동은 구현하지 않는다. 화면의 잔액·금액·수수료는 모두 학습용 가상 정보다.

## 검증

Provider 단위 테스트로 PIN, 금액 범위, 잔액·수수료, 회수 순서, 시나리오 순환, 중복 진행을 검사한다. 위젯 테스트로 320dp·아주 큰 글씨 키패드와 기본 글씨 삭제 문구를 검사한다.

다음 예정 작업은 무인민원발급기 V2이다.

## 실제 에뮬레이터 검증

- 환경: Android Small Phone, Android 15(API 35), 360dp 기본 글씨 및 320dp `아주 크게` 설정
- 설치: 최신 debug APK를 `adb install -r`로 설치해 기존 앱 데이터를 유지했다.
- 따라 해보기: 업무 선택부터 카드 삽입, 연습용 PIN, 계좌와 금액 선택, 거래 확인, 카드·현금 회수, 명세표 선택, 완료까지 직접 진행했다.
- 반응형: 주요 화면을 세로 스크롤로 모두 접근할 수 있었고, PIN 삭제 버튼은 공간이 부족할 때 아이콘 전용으로 전환되며 접근성 라벨을 유지했다.
- 보안: SharedPreferences와 logcat에 연습용 PIN 원문이 남지 않는 것을 확인했다.
- 상태: Android 시스템 뒤로가기도 화면의 이전 단계 콜백을 사용하도록 `PopScope`를 적용했다. 혼자 해보기 미션 안내 또는 첫 단계에서 나가면 활성 일일 미션을 정리한다.
- 회수 순서: 거래 후 카드 회수 전에는 현금 단계로 진행할 수 없고, 카드와 현금을 모두 챙기기 전에는 완료할 수 없다.
- 일일 미션: 활성 ID `atm_solo_complete`를 ATM 흐름 안에서 유지하고 중도 이탈 시 정리하는 로직을 확인했다. 날짜별 ATM 선정 여부는 자동 테스트로 보완한다.

현재 화면은 실제 금융 거래를 수행하지 않으며 실제 카드·계좌번호·PIN을 입력하거나 저장하지 않는다. 에뮬레이터 수동 검증은 대표 따라 해보기 한 회와 선정된 ATM 미션 진입을 중심으로 수행했고, 혼자 해보기 3개 시나리오 순환과 수수료 계산은 Provider 테스트로 검증한다.
